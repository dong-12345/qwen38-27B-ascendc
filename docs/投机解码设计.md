# 投机解码（Speculative Decoding）设计：把 decode 从"每 token 读一遍权重"里解放出来

> 目标：用户要求 **≥5 tokens/s**。
> 结论先说：**27B 单核不可能到 5 tok/s**（地板 0.65 tok/s），投机解码是最有效的倍增器，
> 现实目标 **1.5–2.5 tok/s**；**Moondream3（1.03 GB/token）** 才是能摸到 5 tok/s 的模型。

---

## 1. 为什么必须投机

当前 decode 每次前向只产出 **1 个** token，却要读完整权重（15.73 GB / 27B）：
`15.73 GB ÷ 10.2 GB/s = 1.54 s/token`（单核地板 ≈ 0.65 tok/s）

AX/Axpy-N 把实际速度从 12.48 s/token 压到预期 4.9 s/token（效率 31%），
但**每次前向的"权重租金"是固定的**——要提 tok/s，只能让**一次前向验证多个 token**。

投机解码的收益公式（k = 草稿 token 数，α = 单 token 接受率，平均接受 ≈ (1−α^{k+1})/(1−α)）：

| 场景 | 草稿开销 | 验证开销 | 每轮产出 | 等效 tok/s |
|---|---|---|---|---|
| 现状（AX 后） | — | 4.9 s | 1 | **0.20** |
| k=4, α=0.8 | 0.6 s（0.6B draft） | 4.9 s | ~3.4 | **0.62** |
| k=8, α=0.8 | 1.3 s | 4.9 s | ~5.0 | **0.81** |
| k=8, α=0.9 | 1.3 s | 4.9 s | ~6.1 | **0.98** |
| k=16, α=0.9 | 2.5 s | 4.9 s | ~8.6 | **1.16** |
| Moondream（AX 后 0.9 s/token）k=8, α=0.85 | 0.4 s | 0.9 s | ~5.7 | **4.4** ← 接近 5 |

要 27B 到 5 tok/s 需要"每次验证 ~25 个被接受的 token"，即 k≥32 且 α≈0.95 —— 不现实。

---

## 2. 方案

### 2.1 草稿模型（推荐）
- 选 **同 tokenizer 的小模型**：Qwen3-0.6B / Qwen3-1.7B（int4 量化后 0.35 / 1.0 GB）；
- 板上占用：27B(13.5 GB) + draft(0.35 GB) + KV ≈ 仍可放进 18 GB 空闲显存（实测空闲 ~18 GB）；
- 草稿开销 = draft 的权重流量 ÷ 2.24 GB/s ≈ 0.16 s/token（0.6B）；
- **不需要改 27B 的 kernel**，只加"批量验证"。

### 2.2 验证（关键改动）
投机验证 = 用一次前向算出 k+1 个位置的 logits，然后按贪心/采样规则逐个比对草稿。
对 27B 引擎：**把现有的 `runPrefillChunk()`（layer-major、M=32 批量、Cube 两段式）直接复用**——
它本来就是"一次前向算 M 个 token"，正好是验证需要的形状。

需要新增/确认的点：
1. **多位置注意力**：`full_attn_decode_do` 是单 query 的；批量版需要 M 个 query 各自 mask 到自己位置
   （现成 `full_attn_decode` 已有 causal 逻辑可参数化）；
2. **GDN 层**：`gdn_rgdr_do`/conv 是逐 token 递归的 → 批量验证时必须**按顺序**推进状态（M 次循环，但权重只读一次 —— 这正是收益来源）；
3. **KV cache 回滚**：验证失败时要把多写的 KV（和 GDN 状态）回滚到接受点（记录 checkpoint 即可）；
4. **一致性**：贪心解码下投机结果与直接解码**必须逐 token 相同**（这也是最容易验证的验收标准）。

### 2.3 工程顺序（建议）
1. 先把 **AX/Axpy-N 端到端**跑通并记录（预期 12.48 → 4.9 s/token）；
2. 写"多 token 验证"路径（复用 prefill 批量），**先只验证不投机**：给它 M 个已知 token，检查 logits 与逐个前向一致；
3. 接 0.6B 草稿模型，度量 α（板上实测接受率）；
4. 按 α 调 k，取最优 tok/s。

---

## 3. 验收标准
- 贪心 decode 输出与基线**逐 token 相同**（`ENG27_IDS=... ENG27_GEN=...` 对拍）；
- 报告 k、α、等效 tok/s 三组数据；
- 关掉投机（`ENG27_NOSPEC=1`）可回到普通 decode。

---

## 4. 风险
| 风险 | 说明 | 缓解 |
|---|---|---|
| GDN 状态回滚复杂 | 48 层递归状态，回滚要存 checkpoint | 每轮验证前拷贝状态（48×48×128×128 fp32 = 113 MB，可接受） |
| 草稿模型加载慢 | 板子加载 13.5 GB 已需 85 s | draft 只有 0.35 GB，增量可忽略 |
| 采样非贪心 | 需要 rejection sampling 的正确实现 | 先只支持贪心/temperature=0 |
| 显存 | 27B + draft + checkpoint | 实测空闲 18 GB，够 |

## 1. 调试通道

### 1.1 UART 串口（板载 CH343P）

| 项目 | 值 |
|---|---|
| Windows 设备 | `COM7`（USB-Enhanced-SERIAL CH343，VID_1A86&PID_55D3） |
| 参数 | 115200 8N1，无流控 |
| 登录方式 | 系统账号 **`HwHiAiUser` / `Mind@123`**（手册默认；`root` 默认同密码） |

注意：
- 串口空闲时不会打印任何内容，需要发 `\r` 才会出现 `orangepiaipro-20t login:`。
- 若上一次会话停在 `Password:`，直接回车会以空密码提交并回到 `login:`。
- 板子在忙（如 nmcli 扫描）时 115200 串口会丢字符，批量脚本要按 64 字节分片、每片间隔 ~10ms 发送。

可用脚本（`tools/`）：
- `uart.py` — 读串口 / 登录
- `uart_exec.py` — 登录后按行执行命令（带 sudo 自动应答、写入节流）
- `console_cmds.py` — 更轻量的顺序命令执行器

### 1.2 网络：Windows 移动热点

- 本机热点 **SSID `DONG`，密码 `88888888`**，Windows 通过 `NetworkOperatorTetheringManager` (WinRT) 开启，2.4GHz 频段，网关 `192.168.137.1`。
- 板上 WiFi 芯片是 **AIC8800**（`dmesg` 中 `aic_*` 驱动），2.4G/5G 双频可扫描（能看到 BUCT 5G 的 BSSID），但 Windows 该 Intel BE201 移动热点只跑 2.4G。
- 连接命令（板上）：`sudo nmcli dev wifi connect DONG password 88888888`
- 板子拿到 `192.168.137.163`，与本机互通；实测 LAN 吞吐约 **1.2 MB/s 单流、1.5 MB/s 四流并行**（2.4G 链路瓶颈）。

### 1.3 SSH

- 板端 `systemctl enable --now ssh` 已开。
- 本机密钥 `tools/opi_key`，公钥已写入板端 `~/.ssh/authorized_keys`，免密：

```bash
ssh -i tools/opi_key HwHiAiUser@192.168.137.163
```

## 4. 推理引擎选型（310B 的现实）

| 引擎 | 310B 可用性 |
|---|---|
| MindIE | ❌ 仅 910/310P |
| vLLM-Ascend / SGLang-Ascend | ❌ 仅 910/310P（GDN 算子也只有 310P 版） |
| llama.cpp CANN 后端 | ❌ 依赖 310B 缺失的 NN/融合算子 |
| CANN ATC（ONNX→OM）+ ACL | ✅ 可用（fp16 静态图，需自己导图，7B fp16 约 1.1 tok/s） |
| **llm_simple（手写 AscendC + AWQ 4bit）** | ✅ 最快（同款 20T 实测 7B-AWQ 4.85 tok/s） |
| MindSpore / MindNLP | ⚠️ 仅特定模型（如 DeepSeek-R1-Distill-Qwen-1.5B） |

选择：**llm_simple**（`github.com/lenLRX/llm_simple`，master 分支），因为它自带 310B 的 AscendC 算子库 `libnpu_ops.so`，且直接吃 AWQ 4bit 权重，无需 ATC 转换。

### 4.1 编译

```bash
sudo apt-get install -y libeigen3-dev libsentencepiece-dev libboost-program-options-dev \
  libboost-system-dev libboost-filesystem-dev libgtest-dev libspdlog-dev \
  nlohmann-json3-dev libre2-dev
cd ~/llm_simple && mkdir -p build && cd build
source /usr/local/Ascend/ascend-toolkit/set_env.sh
cmake .. -DCMAKE_BUILD_TYPE=Release && make -j4   # 产出 build/src/llama2_main
```

### 4.2 Qwen3 适配补丁（本项目新增）

llm_simple 原本只支持 `Qwen2ForCausalLM`。Qwen3 架构多了 **per-head QK-Norm**（在 head_dim 维度做 RMSNorm，再算 RoPE）。补丁：

- `src/llama2_layer_npu.hpp`：`Qwen2TransformerLayerNPUImpl` 增加 `has_qk_norm / q_norm_dev / k_norm_dev`
- `src/llama2_layer_npu.cpp`：
  - `Init()` 末尾检测并加载 `model.layers.<i>.self_attn.q_norm.weight.bin` / `k_norm.weight.bin`（head_dim*2 字节）
  - `Forward()` 中在 q/k 投影之后、RoPE 之前调用
    `npu_rmsnorm_layer(out, q_norm_w, q, cur_size*n_heads, head_dim, eps, dt, stream)`
    —— 把 [seq, n_heads*head_dim] 当成 seq*n_heads 行 × head_dim，正好等价于逐头 RMSNorm。

编译验证：`strings build/src/llama2_main | grep qk-norm` 命中即生效。

### 4.3 权重转换

```bash
/usr/local/miniconda3/bin/python scripts/convert_qwen2_awq_weight.py \
  --input_model_path ~/models/Qwen3-8B-AWQ \
  --output_dir ~/models/Qwen3-8B-AWQ-converted
```

转换脚本把每个张量写成 `<参数名>.bin`；AWQ 的 qweight/qzeros 会重排成 AscendC 核要求的 int4 布局。

### 4.4 运行

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
./build/src/llama2_main \
  --config=~/models/Qwen3-8B-AWQ/config.json \
  --tokenizer=~/models/Qwen3-8B-AWQ/ \
  --weight=~/models/Qwen3-8B-AWQ-converted \
  --model_type=qwen2 --device_type=npu \
  --max_seq_len=4096 --max_gen_token=128 --temperature=0.6 \
  --rope_is_neox_style=true --prompt="你好"
```

## 5. 结论：模型能力边界

| 模型 | 310B 可行性 | 实测/预期速度 |
|---|---|---|
| Qwen3.8-27B / Qwen3.5-3.6-3.8 全系（Gated DeltaNet 混合） | ❌ 算子缺失 + 内存不足 | — |
| Qwen2.5-3B-AWQ | ✅ | 8.8 tok/s |
| Qwen2.5-7B-AWQ | ✅ | 4.85 tok/s |
| Qwen2.5-14B-AWQ | ✅ | 1.53 tok/s |
| Qwen2.5-32B-AWQ | ⚠️ 内存极限 | ~0.7 tok/s |
| Qwen3-8B-AWQ（本项目适配） | ✅（新补丁） | 待实测，约 4-5 tok/s |

Qwen3.8-27B 的可行部署方案见 `docs/Qwen3.8-27B-MTP-310P-910B-部署方案.md`。

## 3. 27B 权重转换（group-32，几乎无损）

- 源：`Qwen3.8-27B-AWQ-INT4`（21.04GB，5 shard，2396 tensors，27.78B 参数）
- 目标格式：相位交织 W4（word j = q[j], q[j+KQ], q[j+2KQ], q[j+3KQ]）+ fp16 scale + fp16 `sz=s*z`
- **重新量化误差（真实权重）**：

| group | 平均相对误差 |
|---|---|
| **32（保持源网格）** | **0.0000~0.0002（几乎无损）** |
| 64 | 6.2% |
| 128 | 9.4% |
| 512 | 12.7% |

→ 必须保持 group-32。最终 16.89GB（含 embed/lm_head 也量化成 W4，省 3.5GB）。

## 4. 推理引擎（`host/engine_27b.cpp`）

流程：embed 行反量化 → 64 层（48 层 GDN + 16 层全注意力）+ MLP → final norm → lm_head（W4 GEMV）→ argmax → 自回归。
- 权重**流式加载**（不占用 host 峰值内存）
- GDN 状态：48 层 × 48 v-head × [128,128] fp32 = 151MB；conv 状态 5.9MB；KV cache 32MB
- 支持 `ENG27_IDS`（prompt token ids）/`ENG27_GEN`/`ENG27_TRACE`（逐 kernel trace + logits top-5）/`ENG27_QGATE=split|interleaved`

### 实测（2 层冒烟子集：layer0=GDN，layer1=全注意力，词表截断到 1024）
```
[engine27] meta: 28 tensors, layers=2
[trace] layer0: ln1 → qkv → z → aproj → bproj → conv → l2norm → rgdr x48 → gatednorm x48 → outproj → MLP
[trace] layer1: ln1 → qnorm/knorm → full_attn_decode → oproj → MLP
[engine27] prefill 5 tok in 2.02 s (2.47 tok/s); decode 8 tok in 3.24 s -> 2.469 tok/s (0.41 s/token)
TOKENS 241 431 241 241 241 241 431 241
```
→ **每层约 0.2 s**（含全部大 GEMM），据此**预估** 64 层 ≈ 13 s/token（0.077 tok/s）。

## 5. 打通过程中修掉的 12 类真实限制（AscendC 踩坑记录）

1. 逐元素 `SetValue`/`GetValue` 在非 32B 对齐索引上直接崩（507015）→ 全部改批量 vector + 1 次 `V_S` 同步
2. 树形归约长度必须是 8 的倍数（偏移 32B 对齐）：`rmsnorm_op`(H=5120→20 个元素) 崩 → 改为「len%8==0 才折半 + 末段 8 元素收尾」
3. UB 248KB 硬限制：`w4a16_gemv_gen`(K=17408) 268KB、`mul_silu`(FF=17408) 238KB 崩 → 分块
4. **host 缓冲区尺寸与 kernel 常量不同步**（group-128 的 SBP=48 vs group-32 的 160）→ GM 越界，且错误信息只在 `aclGetRecentErrMsg()` 全文里（`The DDR address of the MTE instruction is out of range`）——**务必打印完整错误**
5. 相位交织打包下，分块内 4 个相位对应 `k = p*KQ + c*256 + i`（跨相位步长），act 片段必须按相位取
6. f16 权重（1 层 out_proj 未量化）传空 scale 指针 → 507015 → 引擎按 `w4/f16` 分发
7. `Cast`(V)→`DataCopy`(MTE3) 必须 `SetFlag/WaitFlag<V_MTE3>`；写回后要 `MTE3_V`
8. 1 元素 DataCopy/Cast 非法；极小（32B）DataCopy 在复杂 kernel 里不稳定 → 输出按 16 行批量写
9. UB→UB 无 3 参 DataCopy → 用 `Muls(dst, src, 1.0f, n)` 代替
10. matmul 需要 `HAVE_WORKSPACE/HAVE_TILING`，会破坏其他 kernel 的自动生成 wrapper → 独立到 `kernels/mm/`
11. `Gather` 在 310B1 可用，level-2 接口索引是**字节偏移**（fp32 表 ×4）；count 可以到 8192
12. 多核不存在（ai_core=1）：blockDim 扫描总时长不变

## 6. 性能分析结论（详见 `docs/310B-性能上限与prefill优化.md`）

- **GM 10.2GB/s 是硬墙**：27B（16.89GB int4）单次前向最少需要 1.65s（100% 带宽），实测 GEMV 0.85GB/s ≈ 8% 利用率
- Cube 高层 API 上限 1.46 TFLOP/s（B 矩阵按 M/128 块重读导致复用率低）→ 手写 matmul 才可能接近 4.6+ TFLOPS
- 多核不存在 ⇒ 无法靠并行提升
- 优化的正确顺序：① 融合 dequant+GEMV（已做，4.5→0.5 B/param）② 手写 Cube matmul ③ GDN chunk 优化 ④ M batching

### 关键实现细节（与官方 Qwen3.5 参考实现对齐）
1. **RMSNorm = 1-centered**：`out = norm(x) * (1 + w)`（Qwen3_5RMSNorm）
   - GatedDeltaNet 的 RMSNormGated **不是** 1-centered（`weight` 直接相乘）
2. **q_proj 布局 = per-head 交错**：`[q_h(256) | gate_h(256)] × 24 heads`
3. **注意力输出门 = sigmoid(gate)**（不是 swish）
4. mrope（`mrope_interleaved=True, sections=[11,11,10]`）在纯文本下退化为标准 rope
5. 模型是 VL + 推理模型（`Qwen3_5ForConditionalGeneration`），对话需带 `<think>` 前缀
